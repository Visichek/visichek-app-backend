MARKETING SITE — FAQ PAGE INTEGRATION
======================================
One endpoint powers the public FAQ page. No auth, no API key, no
tenant context. The payload is fully rendered: sections, items,
header copy. Just fetch and paint.

   GET https://<api-host>/v1/faqs

All field names are camelCase. The response is wrapped in the
standard envelope — the data you want is under ``data``:

   { "success": true, "message": "...", "data": { ...payload... } }

The rest of this doc describes the ``data`` payload.


HOW TO RENDER
=============

The payload has four pieces:

   data.headline    → hero headline ("Frequently Asked Questions")
   data.subheadline → hero sub-line (often null — render only if set)
   data.footerHtml  → contact-us / "have an infrequently asked question?" block
   data.sections[]  → grouped FAQ items


1. SECTIONS  (data.sections[])
------------------------------
Each entry is a section banded by its heading. Render in array
order — they're already sorted.

   {
     "categoryKey": "billing",
     "label":       "Billing & pricing",   // section heading
     "sortOrder":   20,
     "items": [
       {
         "itemKey":   "billing-how-it-works",
         "question":  "How does billing work?",
         "answer":    "<p>Subscriptions renew monthly...</p>",  // HTML
         "sortOrder": 10
       }
     ]
   }

Rendering rules:
 - Render ``label`` as the section heading.
 - Iterate ``items`` in order — already sorted by ``sortOrder``.
 - ``answer`` may be plain text OR HTML / sanitized markup. Render
   with the same HTML-rendering approach you use for blog content
   (eg ``dangerouslySetInnerHTML`` after sanitisation, or your
   markdown / safe-html component).
 - Empty sections are filtered out by the backend — you'll never
   receive a section with ``items: []``.
 - Use ``itemKey`` as your React/Vue ``key`` — it's stable.
 - Use ``categoryKey`` as the section ``key`` and as the URL hash
   anchor target if you want "Jump to section" links
   (``#section-billing``).


2. HEADER + FOOTER
------------------
   data.headline    — always present. Render as the page H1.
   data.subheadline — optional. Render under the H1 if set; skip
                       silently if null.
   data.footerHtml  — usually present (defaults to "Have an
                       infrequently asked question? Email us at
                       support@..."). HTML — render after the
                       FAQ list. Skip if null.

The defaults are sensible and stable — you can render against the
shipped defaults and the marketing team will only edit them when
they actually need to.


3. FRESHNESS
------------
 - The payload is cached server-side and updates within seconds of
   any admin edit. Safe to cache in your CDN for 1–5 minutes.
 - ``data.lastUpdated`` is a Unix timestamp (seconds) of the last
   overlay change. Useful for cache-busting or for showing an
   "Updated YYYY-MM-DD" hint at the bottom of the page.


4. ERRORS
---------
The endpoint is read-only and unauthenticated, so failures are
rare. If you get a non-200, render an empty page (or a hardcoded
fallback) — don't show users a broken page.


5. FULL EXAMPLE
---------------

   fetch("https://api.visichek.com/v1/faqs")
     .then(r => r.json())
     .then(({ data }) => {
       renderHero(data.headline, data.subheadline);

       for (const section of data.sections) {
         renderSectionHeading(section.label, { id: `section-${section.categoryKey}` });
         for (const item of section.items) {
           renderAccordionItem({
             id:       item.itemKey,
             question: item.question,
             answer:   item.answer,   // HTML
           });
         }
       }

       if (data.footerHtml) {
         renderFooterHtml(data.footerHtml);
       }
     });


6. WHAT NOT TO DO
-----------------
 - Don't hardcode FAQs in the site. Admin edits won't reach you.
 - Don't try to sort sections or items client-side — they're
   already sorted by the backend.
 - Don't filter out items you "don't recognise". Treat any
   ``itemKey`` as opaque — the backend may add new ones at any
   time, and the marketing team should see them appear without an
   FE deploy.
 - Don't assume a fixed set of sections. Today: General / Billing
   & pricing / Security & compliance / Support. The marketing team
   may add custom sections at any time.
