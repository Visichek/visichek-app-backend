VISICHEK FREE PLAN — COMPLETE LIMITATION REFERENCE
====================================================
Last updated: 2026-05-16
Source of truth: config/plan_tiers.py (FREE_DENIED_FEATURES + FREE_PLAN)
Frontend live manifest: GET /v1/me/limitations

The Free plan exists for evaluation and very small offices. It is
deliberately stripped down so every meaningful operational feature is an
upgrade prompt. This document is the human-readable companion to the
machine-readable feature_rules / crud_limits / retrieval_quotas /
tenant_caps that live on the plan record in MongoDB.

Everything below is enforced by the PlanEnforcementMiddleware in
core/plan_enforcement.py except where noted.


1. HARD CAPS (TenantCapLimit + StorageLimit)
--------------------------------------------
   - 1 system user (tenant-side staff account)
   - 1 department
   - 1 branch (single location only)
   - 50 visitor records per month
   - 0 appointments per month — appointments disabled entirely
   - 10 documents total (lifetime)
   - 10 MB total storage
   - 2 MB per-file size cap

   Adjustable by application admin: only max_visitors_per_month.


2. DAILY WRITE QUOTAS (crud_limits, reset 00:00 UTC)
----------------------------------------------------
   - 5 visitor creations / day
   - 10 visitor-profile updates / day
   - 2 document uploads / day

   Exceeding any of these returns HTTP 429 QUOTA_EXCEEDED.


3. DAILY READ QUOTAS (retrieval_quotas, reset 00:00 UTC)
---------------------------------------------------------
   - 200 dashboard reads / day
   - 200 visitor reads / day
   - 300 visit-session reads / day
   - 50 document reads / day

   HTTP cache hits still count against these — the cache layer sits
   inside plan enforcement so quota accounting is honest. Limits are set
   generously so normal usage by a single receptionist will not trip
   them; aggressive polling will.

   Exceeding any of these returns HTTP 429 QUOTA_EXCEEDED.

6. SLIM DASHBOARD — GET /v1/dashboard/stats
--------------------------------------------
   Free-plan response contains ONLY:
     - plan_tier:                "free"
     - upgrade_required_for:     ["charts","trends","exports","top-N",
                                  "heatmaps","recent_activity","growth",
                                  "compliance","audit","incidents",
                                  "appointments"]
     - role_view, last_updated, period
     - Counters:                 total_visits, total_visitors,
                                 total_departments, total_system_users
     - Live state:               currently_active, awaiting_checkout,
                                 pending_approval
     - Today snapshot:           visitors_today, check_ins_today,
                                 check_outs_today, new_visitors_today,
                                 returning_visitors_today, denials_today

   Every other field on TenantDashboardStats is null — including all
   charts, distributions, top-N rollups, 7/30-day time series, hourly +
   day-of-week heatmaps, growth deltas (DoD/WoW/MoM), visit-duration
   stats, signup metrics, recent check-in / upcoming appointment lists,
   appointment funnel, operational-quality rates, and the compliance /
   audit / incident sections.

   The frontend should render an upgrade nudge in any section it sees
   as null, keyed by upgrade_required_for.


7. PUBLIC VISITOR FLOW — "POWERED BY VISICHEK" WATERMARK
---------------------------------------------------------
   GET /v1/branding/public/tenant/{tenant_id} returns
       powered_by_visichek: true
   for Free-plan tenants. The frontend renders a "Powered by Visichek"
   watermark on the public registration / kiosk flow whenever this flag
   is set. Paid tiers receive powered_by_visichek: false.

10. NOT YET ENFORCED — DOCUMENTED FOR ROADMAP
----------------------------------------------
   Historical visibility cap (visit session lists clamped to last 7 days
   for free plan) is on the roadmap but not yet wired. Currently free
   tenants can paginate through their full history (subject to the 50
   visitors / month cap so total volume is bounded).

   Webhook / external integration configuration was never built; when
   it lands it will be paid-only by default.
