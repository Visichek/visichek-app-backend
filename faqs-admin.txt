FAQ ENDPOINTS — ADMIN APP REFERENCE
====================================
Three endpoints for the public FAQ page. Same singleton-overlay
pattern as ``/v1/pricing-marketing``. All wire payloads are camelCase
(CaseConversionMiddleware converts on the wire). Response envelope is
the standard ``{ success, message, data, requestId }``.

GET is public; PATCH + DELETE require an application admin token with
the ``patch_faqs`` / ``delete_faq_row`` permissions (granted to the
``all_controls`` and ``content_only`` access presets).


SHAPE OF A FAQ ITEM
-------------------
   {
     "itemKey":     "billing-how-it-works",   // short slug, your natural key
     "question":    "How does billing work?",
     "answer":      "<p>Subscriptions renew monthly...</p>",  // HTML or markdown
     "categoryKey": "billing",                 // null → falls under "general"
     "sortOrder":   10
   }

``itemKey`` is the merge key. Pick a stable slug at create-time —
re-sending the same slug on a later PATCH UPDATES the row; a new
slug APPENDS a new row.

``categoryKey`` is optional. Items without one show under the
default "General" section. Use a custom ``categoryKey`` to group
items into your own section (see CATEGORY MANAGEMENT below).


1. GET /v1/faqs   (PUBLIC — NO AUTH)
------------------------------------
Returns the fully rendered FAQ page. The admin app uses this same
endpoint to render the preview pane of the editor.

Response data shape:
   {
     "headline":    "Frequently Asked Questions",
     "subheadline": null,
     "footerHtml":  "Have an infrequently asked question? Email us at <a href=...>...</a>",
     "lastUpdated": 1747486800,
     "sections": [
       {
         "categoryKey": "general",
         "label":       "General",
         "sortOrder":   10,
         "items": [
           {
             "itemKey":   "what-is-visichek",
             "question":  "What is VisiChek?",
             "answer":    "<p>VisiChek is a security-first visitor management platform...</p>",
             "sortOrder": 10
           }
         ]
       },
       {
         "categoryKey": "billing",
         "label":       "Billing & pricing",
         "sortOrder":   20,
         "items": [ ... ]
       }
     ]
   }

Notes:
 - Sections come back already sorted by ``sortOrder``.
 - Items inside each section come back already sorted by
   ``sortOrder`` (ties broken by question text).
 - Empty sections are dropped from the response.
 - ``footerHtml`` ships with a sensible default ("Have an
   infrequently asked question? Email us at support@...") — the
   admin can override it via PATCH.


2. PATCH /v1/faqs   (APPLICATION ADMIN)
----------------------------------------
Partial update. Returns 202 + queued job.

Body — all fields optional (omit to leave untouched, send empty
list to clear a section entirely):

   {
     "headline":    "Frequently Asked Questions",
     "subheadline": "Quick answers on billing, security, and rollout.",
     "footerHtml":  "<p>Need more help? <a href='mailto:support@...'>Email support</a>.</p>",

     "items": [
       {
         "itemKey":     "billing-how-it-works",   // REQUIRED — merge key
         "question":    "How does billing work?",
         "answer":      "<p>Subscriptions renew monthly. Annual plans are billed upfront.</p>",
         "categoryKey": "billing",
         "sortOrder":   10
       },
       {
         "itemKey":     "compliance-soc2",
         "question":    "Are you SOC 2 compliant?",
         "answer":      "<p>Yes — SOC 2 Type II audit completed in...</p>",
         "categoryKey": "security",
         "sortOrder":   20
       }
     ],

     "categories": [
       { "categoryKey": "billing",  "label": "Billing",  "sortOrder": 20 },
       { "categoryKey": "security", "label": "Security & compliance", "sortOrder": 30 }
     ]
   }

Merge semantics:
 - ``items`` / ``categories`` are upserted by their natural key
   (``itemKey`` / ``categoryKey``):
     - existing key → REPLACES the row in-place
     - new key      → APPENDS the row
     - omit field   → list untouched
     - empty list   → clears the whole list (use with care)
 - Top-level ``headline`` / ``subheadline`` / ``footerHtml``: set
   to a string to overwrite; ``null`` leaves it untouched.

Response: 202 ACCEPTED
   {
     "id":     "singleton",
     "jobId":  "<uuid>",
     "status": "queued"
   }

The job is processed by a worker. The next GET will reflect the
change within a couple of seconds.

Errors:
   401 — unauthenticated
   403 — admin lacks ``patch_faqs`` permission (only ``all_controls``
         + ``content_only`` access presets get it)
   422 — body fails validation


3. DELETE /v1/faqs/{kind}/{key}   (APPLICATION ADMIN)
------------------------------------------------------
Remove ONE overlay row by natural key.

Path params:
   kind ∈ "item"     → key is the itemKey     (eg "billing-how-it-works")
        | "category" → key is the categoryKey (eg "billing")

Examples:
   DELETE /v1/faqs/item/billing-how-it-works
   DELETE /v1/faqs/category/legacy-section

No body. No-ops cleanly when the row is already gone.

Response: 202 ACCEPTED
   {
     "id":     "singleton",
     "jobId":  "<uuid>",
     "status": "queued"
   }


CATEGORY MANAGEMENT
-------------------
Four default categories ship with the system:

   general    "General"                sortOrder 10
   billing    "Billing & pricing"      sortOrder 20
   security   "Security & compliance"  sortOrder 30
   support    "Support"                sortOrder 40

You can:
 - RENAME a default — PATCH ``categories`` with the same
   ``categoryKey`` and a new ``label``.
 - REORDER — change ``sortOrder``. Lower = higher on the page.
 - CREATE a new section — PATCH ``categories`` with a new
   ``categoryKey`` (eg ``"integrations"``), then set items to use
   that key.
 - DELETE a custom section — ``DELETE /v1/faqs/category/<key>``.
   Items that pointed at that key get parked under "general" on
   next render rather than disappearing.


UI WIRING SUGGESTIONS
---------------------
 - Item editor: one row per ``itemKey``. The editor form holds
   ``itemKey``, ``question``, ``answer``, ``categoryKey``,
   ``sortOrder``. "Save" → PATCH with a single-item ``items``
   array. Other items in the overlay stay untouched.
 - Section editor: tabular view of ``categories``. Reordering is
   a PATCH on ``categories`` with the whole reordered set.
 - "Reset to defaults" → DELETE the row by key. The defaults
   (general / billing / security / support) auto-reappear because
   they're code-shipped, not stored.
 - Preview pane: just call the public ``GET /v1/faqs`` after each
   PATCH. The cache invalidates automatically on every write.


PERMISSIONS QUICK CHECK
------------------------
``GET``     — anyone, no token
``PATCH``   — application admin, requires the ``patch_faqs`` permission
``DELETE``  — application admin, requires the ``delete_faq_row`` permission

Granted by these access presets:
   all_controls  → both
   content_only  → both (FAQs are content)
   billing_only  → neither
   support_only  → neither

Audit: every PATCH writes a ``faq.updated`` audit row with a
before/after diff. Every DELETE writes a ``faq.row_deleted`` row.
